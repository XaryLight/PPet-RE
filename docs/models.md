## 支持的格式

| 格式 | 扩展名 | 状态 | 图形数据 | 说明 |
| --- | --- | --- | --- | --- |
| VRM 1.0 / 0.x | `.vrm` | 默认支持 | **内嵌** | GLB/glTF2.0，含 MToon、humanoid、expressions、springBone；单文件即可显示 |
| PMX 2.0 / 2.1 | `.pmx` | 默认支持 | **外部文件** | 二进制，含骨骼蒙皮、材质、变形、显示帧；**只记录贴图路径，不含贴图本身** |
| Live2D | `.model3.json` | 可选后端 | 外部文件 | 需自备 Cubism SDK Core，见 [构建指南](build.md#启用-live2d-后端可选) |
| 模型压缩包 | **`.zip`** | 默认支持 | 随包 | 自动解压并定位包内模型，完整保留贴图目录结构 |

> PMX / VRM 在内部统一转换为「蒙皮网格 + toon 着色」表示，共用同一套渲染管线；
> Live2D 走独立的二维管线。三者共用透明置顶窗口与全屏追踪。

## PMX 请用 `.zip` 导入（重要）

### 为什么

`.pmx` 是 MMD 的模型描述文件，里面的「贴图」字段只是一个**相对路径字符串**
（例如 `tex/body.png`），图像数据保存在同目录或子目录的 `.png` / `.tga` / `.sph` 文件里。
PMX 文件本身**不包含任何图形数据**。

因此单独把 `model.pmx` 拖进程序，典型结果是：

- 模型能加载、骨骼动画正常；
- 但所有材质回退成纯色 —— 也就是社区里说的「**白模**」；
- 日志里出现 `模型引用了 N 个不存在的资源文件`。

一个能正常显示的 MMD 模型通常是这样的目录：

```
初音ミク/
├── miku.pmx
├── tex/
│   ├── body.png
│   ├── face.png
│   └── hair.tga
├── toon/            # toon 渐变贴图
├── sph/             # 球面环境贴图
└── readme.txt
```

### 正确做法

把**整个模型文件夹**打包成一个 `.zip`（保留内部目录结构），然后在
「导入模型」对话框里选择这个 `.zip`。对话框默认第一项就是 `PMX 模型包 (*.zip)`。

```
miku.zip
└── 初音ミク/          ← 可以有一层或多层目录，程序会递归查找
    ├── miku.pmx
    └── tex/*.png
```

程序会：

1. 把 zip 解压到缓存目录（Windows：`%APPDATA%\PPet\models`；Linux/macOS：配置目录同级 `models/`）；
2. 递归定位包内的模型主文件；
3. 以 `.pmx` 所在目录为基准解析贴图相对路径；
4. 加载模型并把「来源压缩包」记录进诊断面板。

> 缓存目录名 = zip 文件名 + 路径哈希，重复导入会先清空旧缓存再解压，不会残留过期文件。
> 配置里保存的是**解压后的模型文件路径**，所以重启后不必再解压一次。

### 包内定位优先级

| 优先级 | 类型 | 说明 |
| --- | --- | --- |
| 1 | Live2D `.model3.json` | Cubism 3 优先于 Cubism 2 的 `.model.json` |
| 2 | PMX `.pmx` | 多个 `.pmx` 时优先选「同目录（含子目录）贴图最多」的那个 |
| 3 | VRM `.vrm` | 单文件模型 |

多个 PMX 的打分规则很重要：社区包里常同时附带多个版本的 `.pmx`，
只有贴图齐全的那个能正常渲染，程序会自动挑出来。

### 贴图路径容错

PMX 多由 Windows 工具制作，路径写法与 Linux 的大小写规则经常冲突。加载时做了三层解析：

1. **直接匹配**：`baseDir + 归一化后的相对路径`（`\` → `/`，去掉开头的 `./`）；
2. **大小写不敏感匹配**：在模型目录里预建索引，按小写的相对路径查找；
3. **按文件名兜底**：目录层级对不上时（PMX 写 `test_texture.png`，实际在 `tex/` 子目录），
   递归索引里按小写的**文件名**查找。

极端情况（缺贴图、贴图在包外）会在日志和诊断面板里明确指出具体缺了哪些文件。

### 快速自检

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| 模型纯色 / 白模 | 贴图没找到 | 打开「模型诊断」看「缺失资源」列表；把 `.pmx` 与贴图一起打包成 `.zip` 重新导入 |
| 日志 `该 PMX 包内没有发现任何贴图文件` | zip 里只有 `.pmx` | 重新打包，把 `tex/` 等目录一起放进去 |
| 配置阶段 WARN `模型引用了 N 个不存在的资源文件` | 单文件导入或贴图路径不匹配 | 同上；诊断面板会列出前若干个具体路径 |
| 模型完全不显示 | 未加载或无网格 | 诊断面板「渲染状态」页会给出「未加载模型 / 网格为空 / GL 错误」等结论 |

## 压缩包导入（通用）

Live2D / MMD 模型在社区里通常以 `.zip` 形式分发。所有格式都支持整包导入：

- 导入时自动解压到缓存目录；
- 贴图、动作等相对路径资源随包一起解压，模型加载时按原目录结构解析；
- 配置阶段会记录并打印包内容统计（条目数、贴图文件数、解压后总字节数、耗时）；
- 识别为 PMX 但**包内一张贴图都没有**时，会给出专门的中文 WARN 提示。

> Cubism 2 的老格式（`.moc` + `.model.json`）**不在支持范围内** —— Cubism 5/6 的 Core 只认 `.moc3`。
> 请先用 Live2D Cubism Converter 转换后再导入。

## 中文路径支持

Windows 上模型的路径经常带中文（下载目录、模型包名、贴图名都可能是中文）。
这里对路径处理做了统一加固，Windows / Linux / macOS 行为一致：

| 环节 | 处理方式 |
| --- | --- |
| 文件读写 | Windows 走 `CreateFileW` 宽字符 API（不经过 ANSI 代码页），Linux/macOS 直接用窄字符 |
| 目录遍历 / 建目录 | `std::filesystem::path` 统一由 `ToFsPath()` 从 UTF-8 构造，Windows 上显式转 UTF-16 |
| 路径回写（存配置、日志） | 统一由 `FromFsPath()` 转回 UTF-8，避免「读得到、存回去变乱码」 |
| 环境变量（`%APPDATA%` / `$HOME`） | Windows 用 `GetEnvironmentVariableW` 宽字符接口，再转 UTF-8 |
| ZIP 条目名 | 按 UTF-8 标志位（bit 11）判定；未置位但字节本身是合法 UTF-8 时也按 UTF-8 解析，否则按系统 ANSI 代码页解码 |
| PMX 贴图路径 | 统一 `/` 分隔 + 大小写不敏感索引，兼容 Windows 工具生成的大小写混用路径 |

> MSVC 的 `std::filesystem::path` 从窄字符串构造时按 **ANSI 代码页**（中文系统即 GBK）解释字节，
> 与 MinGW 行为不同。本项目不直接用 `fs::path(std::string)`，而是通过上表的辅助函数显式转换，
> 因此两种编译器表现一致。
